# Owner Log Management

## Intake Validity Sweep

After forming an intake scope assessment, sweep the project's Next Priorities entries for overlap with the files, design areas, or concepts this flow is likely to touch.

For each overlap, evaluate whether prior work has:

- addressed the item
- contradicted the item
- restructured the area the item refers to
- partially addressed the item

Surface flagged entries before proceeding, and update the log before writing the next routing artifact.

## Merge Assessment

When adding a Next Priorities item, check for existing items that share:

- the same target files or design area
- compatible authority level
- the same workflow type and role path, or a path that can be run as parallel tracks in one cohesive flow

When a merge is identified, replace the overlapping items with a merged item that retains the relevant source citations.

## Standing-Log Verification

The log is a standing document, not only a queue. Its own standing text goes stale when the project's vocabulary changes, and a stale log misdirects every agent that orients from it.

Run this check whenever a flow changes project vocabulary. Examples:

- a role, role family, layer, or workflow is added, renamed, or retired
- a count the log states changes, such as the number of roles or tracks
- the version or numbering scheme changes
- a scope tag or entry category is added, renamed, or retired

Verify two surfaces against the project's current sources, not against memory:

- **Taxonomy:** the scope-tag table and any entry-category or lifecycle definitions the log declares
- **Current-state wording:** every name, count, list, and version identifier in the Current State section

Check counts and lists against the source that defines them, such as the roles folder, the workflow definition, or the release record. Fix stale wording before closure. When intake can already see these edits, name them in the workflow plan.

## Closure Coordination

When closing a flow, complete the overlap sweep and, when vocabulary changed, the standing-log verification before filing the closure artifact. The closure artifact should reflect the already-updated log; it is not the step that defers log cleanup for later.
